# SuzhouMetroRouter · 苏州地铁时刻表路由查询

基于苏州地铁列车时刻表网站（<http://106.14.198.252:8512/station>）的数据，
用 Java 实现：**给定出发车站、到达车站、出发时刻或到达时刻，计算时间最短的乘车方案
（经由车站与换乘点）以及对应的到达/出发时刻。**

零第三方依赖（仅需 JDK 17+），时刻表与站间运行时长均从网站自动抓取并缓存在本地。

## 环境要求

- JDK 17 或更高，且已设置 `JAVA_HOME` 环境变量（构建/运行脚本只认 JAVA_HOME，无其他依赖）
  - Windows：`winget install Microsoft.OpenJDK.21`（或任何 JDK 17+ 发行版）
  - macOS/Linux：系统包管理器安装，如 `apt install openjdk-21-jdk`
- 能访问两个数据源网站（抓取数据时需要）：
  - 时刻表：<http://106.14.198.252:8512/station>
  - 站间运行时长：<https://www.sz-mtr.com/service/guide/map/index_zh.html>

## 快速开始（从零克隆）

```bash
git clone git@github.com:ZekerZhayard-s-Tiny-Works/SuzhouMetroRouter.git
cd suzhou-metro-router

# Windows 用 build.bat / run.bat，macOS/Linux 用 .sh
./build.sh          # 编译（首次约几秒）

# 首次查询会自动抓取所需数据（车站表 + 当日时刻表 + 官网段时，约 3~5 分钟），
# 之后全部走本地缓存，秒级返回。
./run.sh route --from 木渎 --to 桑田岛 --depart 08:30

# 也可以先一次性抓全周一~周日的时刻表（约 3800 个请求，几分钟）
./run.sh crawl --all-weekdays

# 查看全部线路与车站名（查询用站名必须与此一致）
./run.sh stations
```

## 使用方法

```bash
# 1. 构建（需要 JDK 17+，输出到 temp/classes）
./build.sh            # 或 build.bat

# 2. 首次使用先抓取时刻表缓存（默认只抓"今天"对应的星期，全部缓存在 ./temp/cache）
./run.sh crawl                # 抓今天的时刻表
./run.sh crawl --all-weekdays # 抓周一~周日全部（约 3800 个请求，站间并行、约 10 分钟）

# 3. 查看所有线路/车站名（查询用的站名必须与此一致）
./run.sh stations

# 4a. 给定出发时刻：求最早到达
./run.sh route --from 木渎 --to 桑田岛 --depart 08:30

# 4b. 给定到达时刻：求最晚出发（且不迟到）
./run.sh route --from 木渎 --to 桑田岛 --arrive 09:30

# 其他参数
#   --weekday 1..7      按星期几的时刻表查询（1=周一，缺省=今天）
#   --transfer-min 5    同名站跨线换乘耗时分钟数（缺省 5）
#   --refresh           强制重新抓取缓存
#   --concurrency 4     抓取时站间并行数（1..16，缺省 4；服务端吞吐约 5~6 次/秒，再高只会排队）
#   --cache-dir 目录    缓存目录（缺省 temp/cache；所有临时文件都在 ./temp 下）
```

Windows CMD 用 `run.bat` 代替 `./run.sh`，例如：`run.bat route --from 木渎 --to 桑田岛 --depart 08:30`。

## 算法与数据模型

**数据来源（网站实测行为）**

- `GET /station`：服务端渲染 9 条菜单线路（1~8、11 号线）及每条线路的车站顺序。
- `GET /scheduling`（Cookie: `line=线路号; station=百分号编码站名; weekday=1..7; direction=0/1`）：
  返回"小时 → 分钟"茎叶图时刻表。注意三点（都踩过坑）：
  1. **station 必须存在且属于该线路**（百分号编码），否则 302 回首页；1/2 号线因默认站广济南路
     掩盖了这一校验。
  2. **时刻表是每站独立的**（同一线路不同车站的发车分钟不同）。
  3. 站点对 `Cookie` 请求头大小写敏感：Java HttpClient 默认 HTTP/2 会以小写 `cookie:` 发送而被 302，
     因此固定使用 HTTP/1.1。
- 3 号线与 11 号线贯通运营（方向标签均为 花桥/苏州新区火车站），
  构图时把首尾相接的菜单线路**合并为一条走廊**（唯亭站为分界）。
- 个别站的数据缺失时，服务端会自动回退到同站其他线路的数据（如 `line=3; station=唯亭` 返回 11 号线标题）。

**列车运行图重建**

逐站时刻表只记录**停靠**列车的发车时刻，因此载入时先按走廊×方向重建列车：
相邻站按「无越行」顺序配对（hop 取官网相邻时间，配不上再逐档试算取配对最多者），
配对后串成完整行程；配对率低于 80% 的相邻段判为运营分界，不跨段串联
（**6 号线南斜步**：全线只有「苏州新区火车站—南斜步」「南斜步—桑田岛」两段小交路，
没有跨段直通车，靠此判定分开）。大站快车跳过的站可在 6 站范围内多站补链，
跨站时刻按「沿途 hop 之和 − 被跳过站停站时间」估算；终点站与小交路终到站
**不记到达时刻**，按「末次发车 + 至下一站 hop」推算。

运营结构（折返站、段终点、跨走廊贯通、个别相邻站运行时间）由 `official/operations.txt` 显式声明：

- `turnback`：折返站，列车终到于此、不再向后推算（如 2 号线劳动路、7 号线红庄）；
- `terminus`：线路段终点，段内列车因站点页数据截断断链时沿运行时间链延伸到段终点
  （如 3 号线段终点葑亭大道；大站快车中间越站不记）；
- `through`：跨走廊贯通接续（如 7 号线支线车在红庄由 4 号线同向列车接续）；
- `hop`：覆盖相邻站运行时间（官网相邻站对时间有 ±1 分钟噪声，可用长站对校准）。

未声明的走廊/方向按上面的默认规则重建；该文件随构建写入 `network.json` 的 `operations` 字段供网页读取。

**路径计算**

- 时间相关（time-dependent）Dijkstra，状态 =（车站, 所在走廊）：
  - 乘车：在当前站查该走廊该方向可上的列车（按发车升序），乘坐至该车**实际停靠**的
    任一后续站，到达时刻直接取该车时刻表里的到站时刻；同一站只取最早到达的那一班
    （列车不越行，更晚发车的班次不可能更早到达）。
  - 换乘：同名站更换走廊，加换乘时间（缺省 5 分钟）。
  - 到达查询（`--arrive`）：首次上车时刻只能取自出发站发车表，对候选发车时刻二分
    （FIFO 网络到达时刻随出发时刻单调不减），求"不迟到的最晚首班"。
- **多条可行经由的取舍顺序**（字典序）：
  1. 时间——出发查询取最早到达；到达查询取最晚出发（上条二分）；
  2. **换乘候车余量合计最长**——各次换乘走上站台后到发车之间的候车时间之和
     （换乘走行时间为固定参数、不随方案变化，不计入比较；余量越长约等于衔接越从容）；
  3. 换乘次数最少。
  代价为三元组字典序，Dijkstra 用标号修正法迭代松弛至收敛，保证"同一时间下候车余量更充裕"
  的等时方案不会被遗漏（例：苏州火车站→东方之门 14:20 出发，L4 换 L1 与 L2 换 L1 同为
  14:52 到达，程序选择候车余量 3 分钟的前者而非余量 1 分钟的后者）。
- **站间运行时间**：来自苏州地铁官网线路图页
  （<https://www.sz-mtr.com/service/guide/map/index_zh.html>）。该页为 SVG 图 + JS 数据，
  实际可抓取的接口是 `https://www.sz-mtr.com/admin/getTransTickets.do?sid=站号`——返回该站到
  全网各站的乘车时间（分钟）与票价，配合页面 JS 里的站名表（`stationInfo_zh.js`，换乘站键为
  `sX_站号`）和各线路有序站表（`szmtr.js`，`t####` 为作图曲线点），即可得到站对时间矩阵
  （缓存于 `temp/cache/official_pairs.txt`）。

  **注意：远距离站对不可用**。该接口给的是**全网最短时间**（按换乘 + 5 分钟计算），
  例如「索山桥西→金厍桥」3 号线 12 段却返回 18 分钟——实际是按 5 号线 9 段的路由算的。
  因此路由只采信**相邻站对**的官网时间（该部分与时刻表逐段核对一致），
  远距离站的到达时刻一律取运行图里该车的实际到站时刻。
- **换乘走行时间**网站不提供，缺省 5 分钟，可用 `--transfer-min` 调整。

**结果精度说明**：上车与到站时刻均取自时刻表网站（分钟粒度），运行图按相邻站时刻偏移整段串联。
时刻表本身仅供参考（网站原话），实际请以现场为准。

## 目录结构

```
src/szmetro/          Java 源码（无第三方依赖，JDK 17+）
  Main.java           CLI 入口与结果渲染
  Crawler.java        网站抓取/解析/缓存（时刻表 + 官网站间时长）
  Network.java        走廊、换乘关系、时刻表与站对时间矩阵装载
  Router.java         时间相关 Dijkstra 与最晚出发二分
temp/                 运行期产物（git 忽略，均可重新生成）
  classes/            编译输出
  cache/              抓取缓存（corridors.txt / stations.txt / tt_*.txt /
                      official_pairs.txt / official/tickets/ / raw/*.html）
build.sh build.bat    构建脚本（使用 JAVA_HOME）
run.sh run.bat        运行入口
```

## 已知限制

- 站名以 `stations` 模式列出的为准。网站车站列表页缺少个别真实车站（如 1 号线"星海街"、"金鸡湖"），
  这些站无法参与路由。
- 只覆盖时刻表网站提供的 9 条线路（官网已有但时刻表网站未收录的线路，如 10 号线，不在范围内）；
  首末班车之外的时间查询会返回当日无可达路线或无法按时到达。
- 周一至周日时刻表分别缓存；`--weekday` 缺省按"今天"取表。
- 两个数据源均为非官方接口/页面，若站点结构变化需要同步调整解析代码。
